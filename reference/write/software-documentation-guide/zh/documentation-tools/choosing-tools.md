# Choosing tools for documentation

文档团队最重要的任务之一，是选择用哪些工具来生产文档。市面上的选择非常多：既有收费、可在后端替你承担大量工作的商业方案，也有可深度定制、但需要投入时间与学习成本的静态站点生成器等。

如何在「文档工具版图」里做出适合自己情境的选择？下面列出一些值得自问的问题与需要留心的坑。

## Questions to ask

- **预算**——同时考虑资金与时间。  
- **需要哪些输出形态？** 常见包括：网站、PDF、Word、产品内嵌、eBook、Salesforce / Zendesk / 帮助中心等。  
- **团队具备怎样的编程能力？** 包括会哪些语言；你自己与团队愿意学什么；公司内部还能调动哪些开发资源。  
- **是否愿意直接编辑 HTML/CSS/JS？** 有些工具把版式与交互都交给你；另一些则提供更多可视化辅助。  
- **偏好 WYSIWYG 还是纯文本编辑器？** 无论偏好如何，都需要预览与评审环境。  
- **专家审阅流程打算怎么做？** 有些工具按审阅者人数收费，或需要培训非技术审阅者。  
- **公司是否已有支持门户（Zendesk、Freshdesk、Salesforce Service 等）？** 其知识库可能是现成选项。  
- **公司已有哪些工具栈？** 通常复用现有平台（如 Confluence、SharePoint）比再建一个新入口更容易。  
- **是否计划使用 Git/Subversion 等版本控制？** 版本控制对内容管理很有价值，但也有学习曲线；若采用，尽量选择公司已在用的系统。  
- **内容复用 / 单一来源（single sourcing）需求有多强？**  
- **是否使用标记语言？** 若使用，是 reStructuredText、Markdown、AsciiDoc、DocBook 还是 DITA？  
- **预计有多少贡献者与审阅者？** 许可证与培训成本会随之上升。  
- **是否需要 CI/CD 流水线集成？**  
- **是否需要翻译流程？** 若有，要确保工具链与翻译流程兼容。

## Considerations and "gotchas"

- 静态站点生成器很强大，但搭建与调优的时间成本可能接近采购商业工具；可考虑聘请熟悉该工具的专家。  
- 明确长期维护责任人：谁负责升级工具链？出故障时谁处理？  
- 多数工具提供主题起步模板，但企业通常需要品牌化与流程定制，这同样耗时。  
- 内容复用能力因工具而异；要清楚「能复用什么、由谁复用」的限制。  
- 有些工具内置链接维护；有些则要靠你全局查找替换——页面迁移与删除很常见，要有预案。  
- 导入/导出需求：内容是否需提供给第三方或其他系统消费？是否要从代码仓库抽取示例等。
