# DocOps

作者：Jodie Putrino 与 Write the Docs 社区

## What is DocOps, anyway?

随着 [Docs as Code](docs-as-code.md) 等实践普及，技术写作领域也出现了「DocOps」这一专精方向。

它究竟指什么？谁在「做」DocOps？这些问题在 2021 年 Write the Docs 北美 Portland 非正式会议上被广泛讨论；本页整理了当时会话中的部分观点。

概括地说，DocOps 类似 [DevOps](https://www.atlassian.com/devops)，但关注点从通用软件开发转向**文档的创建、管理与发布**全流程自动化与协作。

借用 Atlassian 对 DevOps 的表述，我们可以粗略把 DocOps 理解为：

> 「一套旨在自动化并整合**跨工程、产品、支持与技术写作团队**的文档开发流程的实践。」

与 DevOps 一样，DocOps 强调协作与持续改进。下图在传统 DevOps 生命周期基础上改编，用于示意 DocOps：

## Who practices DocOps?

DocOps 实践者或团队可能承担：

- 选型并支持文档工具链（标记语言、静态站点生成器、托管等）。  
- 定义流程与协作方式，包括文档在敏捷等方法论中的位置。  
- 制定文档优先级与交付物。  
- 培训作者以便贡献文档。  
- 管理内容。  
- 构建并维护 SSG 主题。  
- 为文档实现与产品一致的多版本策略。  
- 编写并维护构建脚本。  
- 降低参与门槛，让写文档更简单、甚至更有趣。

列表并非穷尽；若你的职责与上述有交集，你可能已经在做 DocOps。

DocOps 常与 docs-as-code 联系在一起，但并非必然：即便使用 DITA、CMS、wiki 等，只要你在上述领域深度参与，也很可能属于 DocOps 范畴。
