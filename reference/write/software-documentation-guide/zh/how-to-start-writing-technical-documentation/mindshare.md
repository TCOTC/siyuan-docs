# Building documentation mindshare in a company

在公司里形成「重视文档」的文化很棒，但要真正建立这种文化并不容易。下面提供一些思路与实践建议。

## State the problem

组织内部的沟通问题往往很庞杂。建议从小处、可落地的目标开始。例如：

> 我们将解决工程组织内部项目文档不足的问题。

## Start in engineering

从工程团队切入通常最容易推动文档文化：先拿到只做「工程内部」文档的许可会更简单，例如：

> - 项目文档
>
> - 运维文档  
>   - 手册（Playbooks）  
>   - 监控信息
>
> - 最佳实践
>
> - 风格指南

## Gather input

规划会议应邀请各团队代表；他们不必每次都出席，但讨论需要公开透明，这样结果更可信，也能覆盖更多使用场景。

## Build a taxonomy

许多文档体系是「自然生长」出来的，等于没有体系。若能先搭好结构并在项目间保持一致，会省掉很多混乱。

> [!NOTE]
> 你必须能回答「这段内容应该放哪里？」这个问题。

## Make it easy

上手步骤要尽可能简单直接。多数人不喜欢变化，新工具本身就会引发抵触，因此要让起步成本尽量低。

### Build templates

理想情况下，几秒内就能生成项目文档的基础骨架；并约定统一的文档层级，让大家知道去哪里找信息。

## Have regular meetings throughout the process

建议安排每周例会跟踪各阶段进展：大家有固定场合讨论问题与想法，也能感受到项目在推进。上线后要持续用会议推动采用与收集反馈。

### Make it long-term

好的文档体系需要长期维护、重组与治理。若只把项目当成「把工具搭好就结束」，而没有长期投入，往往会像上一套系统一样失败。
