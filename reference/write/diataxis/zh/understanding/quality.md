# 走向文档质量的理论

Diátaxis 是一种追求文档*质量*的方法。

「质量」一词有失去部分含义的危险：谁都赞成，却很少有人敢严谨地描述。我们都想要高质量文档，却较少明确说明*到底*指什么。

尽管如此，被问及时我们大都能举出「高质量文档」的例子，也能在见到疏漏时指出来——而且常常彼此能够认同。可见我们对质量仍有一把还算有用的抓手。

若在文档中追求质量，不妨把这份抓手再攥紧些，多想一想——这里试着用**功能质量**与**深层质量**的区分来把概念磨得更利。

## 功能质量

我们需要文档达到*准确*、*完整*、*一致*、*有用*、*精当*等标准。这些可称为**功能质量**的面向。任一项未达标，就意味着没能履行一项关键职能。

功能质量的各条属性彼此**独立**。文档可以准确却不完整；可以完整却错漏百出、前后矛盾；也可以准确、完整、一致，却仍然毫无用处。

达到功能质量，意味着在多个彼此独立的维度上持续达到可客观衡量、且水平很高的标准。这需要纪律、对细节的关注，以及扎实的技术能力。

对写作者更苛刻的是：只要有一条未满足，读者往往立刻就能察觉。

## 深层质量

还有另一些特质，可称为**深层质量**。

仅有功能质量并不够，甚至单把它当作目标也称不上令人满意。真正出色的文档，其质量还包含一些无法被「准确、完整」等项所穷尽的方面。

例如：

- *用起来感觉舒服*
- *有节奏、有流动感*
- *贴合人的需求*
- *有美感*
- *能预判用户*

与功能质量不同，它们不能靠核对或量表来检验，却仍能清楚辨识。我们遇到时，一般（不总是，因为也取决于读者自身能力）能认出来。

这些就是*深层质量*的特质。

## 差别在哪里？

深层质量的面向，在性质上似乎与功能质量确实不同。

一份文档可以处处满足功能质量，却仍然缺乏深层质量。准确、一致（甚至很有用）却别扭、难用的例子比比皆是。

也请注意：功能质量如完整与准确，彼此**独立**；深层质量如流动感与预判用户却难解难分、**相互依存**。很难想象一件事若不合乎人的需求，用起来仍会「感觉很好」。

功能质量的面向在某种意义下可以**测量**——有时真能用数字（例如完整度）。*流动感*这类品质则显然不行，只能去追问、去省察。此时需要的不是**测量**，而是**判断**。

功能质量是**客观**的——属于世界。准确指的是文档在多大程度上符合它所描述的世界。深层质量不能靠拿世界来比对来判定。它是**主观的**，也就是说，只能在体验主体——人——的需求这一光下来评估。

而且，深层质量**以**功能质量**为先决条件**。一份文档可以准确、完整、一致却谈不上卓越；但若不准确、不完整、前后矛盾，就绝不会有深层质量。若内容不准确，用户不会觉得它美；若前后矛盾，人也不会享受那种被预判、被照顾的感觉。一旦撞见这些硬伤，阅读体验就毁了一大半。

最后，对写作者而言，功能质量的各项往往像负担与**约束**：每一条都是可能不及格的考验；即便此刻达标，下一版、下一次更新又要把工作放到被书写对象上再对一遍。而像预判需求、保持流动这些面向，则像是**自由**，是创意与品味的用武之地。要达成功能质量，须**服从**约束；要达成深层质量，须**创造**。

| 功能质量           | 深层质量           |
|--------------------|--------------------|
| 彼此独立的特征     | 彼此交织的特征     |
| 客观               | 主观               |
| 以世界为参照来度量 | 以人为参照来评断   |
| 深层质量的前提     | 以功能质量为条件   |
| 体现为约束         | 体现为自由         |

## 如何辨认深层质量

想想我们会怎样评判衣物的质量。衣服首先要有*功能质量*（保暖、透气、耐穿），这些可客观衡量。你不必是服装专家，也能判断这些是否过关。进水了、一撕就破——就谈不上质量。

但衣物还有另一些品质，不能仅靠客观量表衡量；要看出它们，得对衣服有一定理解。料子的好坏、做工未必一眼可见。衣片是否挂得顺、动得自然、剪裁是否老到，至少要培养出一点眼光。这些属于*深层质量*。

但：就算说不出*好在哪里*，人仍然能很清楚地感到*这就是好*，因为**穿起来舒服**，因为愿意穿。不必是专家，也能察觉走动时是否自在、是否贴身跟体。*身体知道*。

文档也是如此。要说出优秀文档*妙在何处*，也许需要行家的眼光；但要感到*它好*，却不必。好的文档**用起来舒服**；你会在顺畅使用中获得满足——像合身、像跟着你动。

我们的读者未必说得出好在哪里、差在哪里；他们也许只注意到功能质量里较表面的部分，把误当作深层上的卓越。这都不要紧——**感觉**好不好，才重要。

但我们作为写作者，需要清楚、有效地理解「好文档」由何构成。既要能辨认*它好*，也要能说明*好在哪里*；还要理解人们使用时的*感受*。

要产出深层质量，靠的就是这种能力。

## Diátaxis 与质量

功能质量的责任，来自对「文档这门技艺」各项要求的认真履行：扎实的技术域知识与技能、把整片地形收束成一张单一、连贯、前后一致的地图的能力。

**Diátaxis 不能替你在文档中实现功能质量。**它只与深层质量的某些面向相关——有的多、有的少——不过若深层质量的各条彼此缠在一起，它也会间接触及全部。

### 让功能质量的疏漏现形

尽管 Diátaxis 不能提供、不能*给*我们功能质量，它仍能帮上忙。

它很擅长*暴露*功能质量上的缺口。人们常注意到：用 Diátaxis 去套现有文档时，许多以前被掩盖的问题会突然变得显眼。

例如：Diátaxis 主张 [参考文档的架构应反映其所描述代码的架构](../four-modes/reference.md)。这样一来，文档中的空白会清楚得多。

又如：把阐释性文字从教程中搬出去（依 Diátaxis 的要求）之后，读者被丢着自思自量、缺乏引导的段落，往往就一下子突出起来。

但就功能质量而言，Diátaxis 原则能扮演的只有*分析*角色。

### 创造深层质量

在深层质量上，Diátaxis 能做得更多。

例如，它用建立在用户需求上的文档模式来描述需求，其分类本身就是对需求的回应。

于是必须认真组织这些分类、安排材料与内部关系、在不同部分采用相应的形式与语言——作为贴合用户需求的方式。

又例如，Diátaxis 直接关涉*流动*。所谓流动——不论在文档还是别的生活场景——我们体验到的是从某一阶段、状态到下一阶段的推进，自然、不勉强，与当下关切以及身心一般如何运作都相谐。

Diátaxis 通过避免破坏节奏来维护流动——例如某条离题跑进了阐释，打断了操作指南，这种对目的与稳定推进的干扰就可以减少。

如此等等。

### 理解其局限

必须明白：追求深层质量时，Diátaxis 永远不可能*独力*完成一切。

例如，它*有助于*在整体形态上趋近美，却并不能单靠它就让文档变美。

Diátaxis 给的是原则，不是配方。更不可能绕开用户体验、交互设计乃至视觉设计等学科所需的技能与洞见，就一步登天。

使用 Diátaxis 并不保证深层质量。深层质量的诸般特征永远在被重新协商、重新诠释、重新发现、重新发明。而 Diátaxis *能*做的，是为文档中的深层质量提供若干*可能*成立的条件。
