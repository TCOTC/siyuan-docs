# 教程与操作指南的差别

在 Diátaxis 中，教程与操作指南被严格区分。现实中这一区分常常不被遵守；事实上，软件产品文档里**最常见**的混淆，就发生在*教程*与*操作指南*之间。

那么：二者到底*有何*不同？为何要紧？又为何会混淆？

都是好问题。先从最后一问说起。*若这条区分当真如此重要，为何又不那么显眼？*

## 共同点

在重要方面，教程与操作指南确实相像。二者都是实践型指引：都包含要读者照做的说明。目的不是解释或传递信息，而是引导读者去*做*，而不是去*知道或理解*什么。

二者都给出步骤，并承诺照做就能成功。对没有实机在手、不准备动手的读者，它们都意义不大。二者都描述有序动作；不按顺序，就很难期待成功。

它们亲缘很近，像许多近亲一样，乍看容易弄混。

## 要紧的是用户此刻的需求

Diátaxis 坚持：文档里真正要紧的是读者的需求；抓住这一点，才能正确区分教程与操作指南。

有时读者在**学习**，有时在**工作**。文档必须同时服务这两种需求。

教程服务的是学习情境中的读者。其义务是*提供一次成功的学习体验*。操作指南服务的是工作情境中的读者。其义务是*帮助用户完成一项任务*。需求与义务全然不同，这正是必须区分教程与操作指南的原因：教程**面向学习**，操作指南**面向任务**。

## 学习与工作

举一个具体领域的例子。假设你是医生：需要习得并运用临床实践技艺。

作为医生，有时你在工作情境中*运用技能*，有时在学习情境中*习得技能*（出色的医生即便资历很深，也会持续进修）。

### 学习

训练早期，你会学习缝合伤口。从实验室开始，和同学坐在台前，面前摆着小小的皮肤垫（皮肤垫是多层的合成材料块，模拟表皮、脂肪等组织；硬度与触感接近真人皮肤，切割与缝合时的行为也有些相似）。你会拿到你需要的一切——手套、手术刀、针线等等——然后一步一步被演示该怎么做、做了会发生什么。

接着轮到你自己。你拿起刀，战战兢兢地在垫子上划过表层，切出一道浅浅的口子（助教或许会打趣：这块垫子做错了什么，值得你狠狠一道划痕）。邻座看着自己歪歪扭扭、深浅不一的切口，像斗殴现场一样沮丧。

几经尝试与教员纠正之后，你总算切出一条还算干净、多半穿过脂肪层而未伤及肌肉的切口。胜利！

<img src="https://www.diataxis.fr/_images/suture.jpg" class="sidebar" alt="" />

但你还得把它缝回去！教员灵巧精准地演示如何把垫上的切口缝拢，几针下来整整齐齐。而你这边线绕错手、拿错方向、放错地方，针会掉，线会脱，还会因为违背无菌操作挨骂。

终于你真开始缝合。下针位置不对，切口边缘撕扯。成品一片拉扯褶皱、针脚粗陋。助教对你以为还算像样的地方也要批评几句。

但*你已经缝了第一道伤口*。你会一次又一次回到这堂课，笨拙会逐渐变成自信的操作。你会获得基本胜任感。你会**在做中学**。

这就是教程。它是*一课*，安全地落在教员——照顾学生利益的老师——手中。

### 工作

再想工作中的医生。你已经胜任，缝合一类临床技能以及许多别的技能都已内化，能在真实医疗情境中每日综合运用。

以常规阑尾切除术为例。临床手册会列出手术室所需设备与人员，说明团队站位，如何摆放器械架与监护设备，并按步骤写出团队要执行的动作，直到正式交接给术后团队。

<img src="https://www.diataxis.fr/_images/operation.jpg" class="sidebar" alt="" />

手册会写切口该开在哪里，却取决于你做开放还是腔镜、有无术前影像等等。对婴幼儿患者，或术中转为开放阑尾切除术，会有特殊步骤或检查。许多步骤会是*若如此则如彼*的形式。

手册帮助确认步骤顺序正确、无遗漏。团队会据此核对要点；有时术中也会翻阅。

即便常规手术，临床手册也有步骤与核对清单。这些是操作指南。不是用来*教*你——技能你已有，流程你已知——而是要在临床实践中安全地引导你完成特定任务——**它们服务的是你的工作**。

## 理解这条区分

医学院里的一堂课与一本临床手册之间的差别，就是教程与操作指南的差别。

| 教程 | 操作指南 |
|----------|--------------|
| 教程的宗旨是**帮助学员获得基本胜任**。 | 操作指南的宗旨是**帮助已胜任的用户正确完成某一具体任务**。 |
| 教程**提供学习体验**。技能通过动手实践习得；教程要紧的是学习者*做了什么*、做时有何感受。 | 操作指南**指挥用户的工作**。 |
| 教程遵循**严密管控的路径**，从既定起点走向既定终点；沿途学习者必须经历课程所要求的那些*遭遇*。 | 操作指南追求成功的*结果*，沿最安全、最稳妥的路径指向目标，但**路径无法被完全管控**：这是真实世界，任何事都可能打断行程。 |
| 教程**让学习者熟悉工作**：工具、语言、流程，以及操作对象的反应方式等等；职责是介绍它们，制造结构化、可重复的体验。 | 操作指南可以且应当**默认读者已熟悉这一切**。 |
| 教程发生在**人为设定的环境**里，学习场景尽可能预先铺好，以保证成功体验。 | 操作指南适用于**真实世界**，你必须应对世界抛来的一切。 |
| 教程**消除意外**。 | 操作指南必须**为意外做准备**，提醒意外可能出现，并给出应对指引。 |
| 教程沿单一路径推进。**不提供选项或岔路**。 | **操作指南通常会分叉分支**，描述通往同一目标的不同路线：*若如此则如彼。在……的情形下，另一种做法是……* |
| 教程**必须安全**。学习者不应受伤；应总能回到起点重来。 | 操作指南**不能保证安全**；常常只有一次做对的机会。 |
| 在教程中，**责任在教师**。学员陷入困境，应由教师收拾。 | 在操作指南中，**责任在用户**，要自己摆脱困境。 |
| 学习者**可能根本没有足够能力提出教程正在回答的问题**。 | 操作指南可以假设**用户一开始就问对了问题**。 |
| 教程对**基本细节**十分明确——在哪里做、东西放哪、如何摆弄对象；照顾身体性的体验——医学例子里按多大力、怎么握持器械；软件教程里可能是命令敲在哪、要等多久。 | 操作指南把这些当作**默会知识**——包括身体的默会。 |
| 教程在方法上**具体而特定**：指向我们为学习者精心布置的特定工具、材料、流程与条件。 | 操作指南必须采取**一般化**路径：许多东西事先未知，或在每个真实案例中都不同。 |
| 教程**传授可迁移的技能与原则**，日后可用于无数情境。 | 用户跟随操作指南是为了**完成某一具体任务**。 |


这些区分没有一条是任意的。它们都来自**学习**与**工作**之间的差别——我们认为这是理解文档读者需求时的关键分野。

## 「基础」与「进阶」

一种常见但可理解的混淆，是把教程与操作指南的差别当成**入门**与**进阶**的差别。

毕竟教程面向学习者，操作指南面向已熟练的实践者；教程必讲基础，操作指南要处理学习者暂不应面对的复杂情形。

但事情不止如此。想想临床流程手册：可以是极低复杂度的常规流程，也可以是文书填写、废弃物处置之类的琐碎步骤。*操作指南完全可以、也确实常常应当覆盖基础流程。*

同时，即便已是合格医生，你也会一次次回到训练情境。其中有些极其进阶、专精，参与者本来就需要很高的起点。

假设你是一位资深麻醉医师，参加「困难新生儿插管」课程：实操部分仍然是学习体验——在教员照管下的一堂课，让你做特定练习以磨练技能——就像多年前你第一次学缝合那样。

复杂程度与入门门槛全然不同，但形式相同，所要满足的需求类型也与当年那堂入门课一致。

软件文档也一样：教程可以讲复杂、进阶的内容；操作指南也可以覆盖基础、家喻户晓的操作。差别在于它们服务的需求：**读者的学习**，还是**读者的工作**。

## 安全与成功

理解这些区分以及坚持它们的理由，对写出成功的文档至关重要。若临床手册把教育与实操混为一谈，一边教学一边指导真实手术，会成为字面意义上的致命文本。

在软件文档等领域，我们往往侥幸过关，因为混淆很少致命。但我们仍会给用户带来大量琐碎的不便与不快——每发布一篇没想清楚是要帮读者**习得技能**还是**运用技能**的教程或操作指南，我们都在加深这种伤害。

何况也伤害我们自己。用户并非非用我们的产品不可。若文档不能带他们成功——若不能满足他们在与产品互动某一阶段的真实需求——只要可以，他们就会另寻他处。

教程与操作指南的混淆绝不是文档混同里唯一的一种，却是最容易犯的一种；也格外有害，因为它可能绊住我们希望转化为忠实用户的新手。为了这些用户，也为了我们自己的产品，把这条区分做对，是成功的关键之一。
