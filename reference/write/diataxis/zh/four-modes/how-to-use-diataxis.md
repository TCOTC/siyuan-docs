# 把 Diátaxis 当作工作方式的指南

Diátaxis 既指导**文档写什么**，也指导**文档工作如何开展、如何执行**。

多数技术文档工作者在干活时都要不断决定**怎么干**。有些场景下文稿只需交付一次、完整终稿即可；更常见的是**持续项目**，例如与不断演进的产品并行开发。许多人还会接手**改进**甚至**收拾烂摊子**式的一整套文档。

Diátaxis 提供的工作方式，与文档圈里许多**习以为常的做法**相反。尤其它不鼓励先做宏大规划、自上而下推进，而偏好**小而灵敏的迭代**，让整体模式从中自然浮现。

## 把 Diátaxis 当指南，不要当计划

Diátaxis 描绘的是文档的**完整图景**。但它所提出的结构，并不是要你当成必须在文档里**填满的计划**。它是**指南**，是一张地图，帮你确认自己是否站在合适的位置、是否朝着合适的方向前进。

Diátaxis 的意义在于：给你一套思考与理解自己文档的方式，让你更清楚文档在做什么、你想对它做什么。它提供工具，帮你评估文档、找出问题所在，并判断可以如何改进。

## 不必为结构焦虑

结构对文档至关重要，但**使用 Diátaxis 并不意味着要把精力花在「先把结构弄对」上**。

只要你持续依 Diátaxis 给出的提示去做，文档最终会呈现 Diátaxis 式的结构——那是因为文档**被改好了**才变成那样，而不是反过来：先硬套结构再指望文档变好。

入门 Diátaxis 并不要求你立刻把文档切成四大块。**绝不意味着**要先建空的教程 / 操作指南 / 参考 / 阐释分区却里面什么也没有。别那样做，那很糟糕。

相反，按下面两节所述的工作流，在符合 Diátaxis 原则的地方抓住改进机会去改，让文档逐渐显出某种形状。到了某个阶段，你所做的修改会**自然要求**把材料挪到某个 Diátaxis 标题之下——顶层结构就是这样形成的。换句话说，**Diátaxis 是从内部改变文档结构的**。

## 一次只做一步

Diátaxis 强烈主张某种结构，但无论现有文档状态如何——哪怕按任何标准都是一团糟——**总可以迭代式地**把它变好。

人自然想攒一大块改动再发布，好每次都有像样的成果可展示。要抵制这种冲动：**朝正确方向迈出的每一步都值得立刻发布**。

尽管 Diátaxis 意在提供文档的宏观图景，**不要试图一口吃掉整张图景**。既无必要，也无益处。Diátaxis 是为引导**小步**而设计的；坚持小步前进，自然能走到想去的地方。

## 先随便做点什么

若要收拾巨大烂摊子，人很容易想推倒重来。同样要克制。就「按 Diátaxis 改进文档」而言，不必刻意到处找问题。更好的用法如下：

**选一样东西**——文档里的任意片段。若你还没有明确想修的目标，别去找「突出问题」。就看此刻眼前有什么：你正在编辑的文件、刚读完的页面——什么都行。若没有合适的，就**随机**挑一段。

**评估它**。接下来带着批判眼光审视这段内容。最好足够小，不要超过一页——更小更好，一段或一句。用 Diátaxis 所要求的标准去挑战它：*它对应哪种用户需求？满足得如何？增、删、改、移什么能更好服务该需求？其语言与逻辑是否符合该文档模式的要求？*

**决定做什么**。根据上述回答决定：*哪**一个**下一步行动能在这里立刻带来改进？*

**去做**。完成这**一个**下一步行动，并**视为已完成**——即发布，或至少提交变更。别觉得还必须多做点什么才算「像样的改进」。

然后回到循环起点。

这样做能减轻文档写作中最令人瘫痪、也最麻烦的压力之一：**不知该做什么**。它让工作持续朝正确终点流动，而不必在计划上耗费心力。

## 让工作有机生长

人强烈倾向于「计划—执行」循环以追求结果。但那不是唯一方式，写文档时往往还有更好的路。

### 形态良好的有机生长

文档的一个好模型是**能适应外部条件、形态良好的有机生长**。有机生长发生在**细胞**层面。整体结构由各类细胞按各自规则健康发育来保证，而不是反过来由外部自上而下硬套结构。好的结构从**内部**生长出来。

文档亦然：遵循 Diátaxis 给出的原则，文档会获得健康的结构，因为其内部构件本身是良构的——像生物体一样，**由内而外**、一次一个细胞地自我搭建。

### 完整，而非终稿

想想植物。作为生命体，植物**永远不会「终稿」**——它总能继续生长，进入下一成熟阶段。但在从种子到参天大树的**每一阶段**，它又是**始终完整**的——从不缺一块。在任意时刻，它都处于与该发育阶段相称的状态。

文档同样永远不会「终稿」，因为它必须持续适应产品与用户需求，也总能进一步发展与改进。

但它可以**始终完整**：对用户有用、与当前发展阶段相称、结构健康，并准备好进入下一阶段。
